# АгроСмена CRM — desktop и ручная синхронизация

Desktop CRM для Windows. Без подключения к серверу продолжает работать локально
с SQLite-файлом `%LOCALAPPDATA%/AgroSmenaCRM/data/crm.db`. По кнопке выполняется двусторонний обмен с Django API.

## Возможности

- главная страница с показателями, последними сделками и ближайшими задачами;
- создание, редактирование, поиск и удаление клиентов;
- создание, редактирование, поиск, фильтрация и удаление сделок;
- создание, редактирование, поиск, фильтрация и удаление задач;
- двусторонняя синхронизация по UUID, включая изменения и удаления;
- проверка обязательных полей и суммы сделки;
- автоматическое создание базы при первом запуске.

Перед удалением клиента приложение предупреждает, что все его сделки также будут
удалены. Удаление выполняется каскадом в одной транзакции. Задачи сохраняются,
а ссылки на удалённого клиента и его сделки очищаются. Enter в подтверждении
удаления выбирает «Да». Сумма новой сделки изначально пустая; если оставить её
пустой при сохранении, записывается 0. Дробную часть можно вводить через точку или запятую.

## Архитектура

```text
UI → Services → Repositories → SQLAlchemy → SQLite
```

Основные каталоги:

- `app/models` — SQLAlchemy-модели;
- `app/repositories` — запросы к данным;
- `app/services` — бизнес-правила, валидация и DTO;
- `app/ui` — окно, страницы и диалоги PySide6;
- `app/core` — конфигурация и подключение к SQLite;
- `tests` — интеграционные и UI smoke-тесты.

## Запуск

В PowerShell из каталога проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

При первом запуске автоматически появится `%LOCALAPPDATA%/AgroSmenaCRM/data/crm.db`.

## Синхронизация с Django

Сначала обновите сервер (из каталога `crmserver`, с активной `.venv`):

```powershell
python tools/local_postgres.py start
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

Перезапустите уже работающий сервер после обновления. Создайте организацию и аккаунт
на `/register/` либо попросите администратора добавить вас в существующую организацию.
В desktop нажмите «Войти на сервер», введите адрес, логин и пароль, затем
«Синхронизировать». При первом обмене подтвердите привязку существующей локальной базы.

- Одна SQLite-база привязывается к одному адресу сервера и UUID организации.
  Передача этой базы в другую организацию блокируется, в том числе после сетевой ошибки.
  Для другой организации используйте отдельную базу/профиль установки; переключателя
  нескольких рабочих пространств пока нет. Не удаляйте таблицу привязки вручную.
- После выхода локальные данные остаются доступны офлайн: это не защита SQLite от
  других пользователей Windows. Пользуйтесь отдельными учётными записями ОС.
- Пароль не сохраняется. Токен шифруется Windows DPAPI для текущего пользователя ОС
  и хранится в локальной SQLite, поэтому вход восстанавливается после перезапуска.
  Кнопка «Выйти с сервера» удаляет сохранённый токен. Сессия действует до 12 часов;
  смена пароля, удаление участника и смена организации прекращают доступ.
- HTTP разрешён только для loopback (`localhost`, `127.0.0.1`, `::1`), удалённый сервер
  требует HTTPS. Для подключения с другого компьютера нельзя указывать его адрес как localhost.
- При конфликте побеждает больший `updated_at` (UTC), при равенстве — сервер.
  Проверьте часы Windows; сервер отклоняет время более чем на 5 минут в будущем.
- Удаления имеют UUID и время изменения, хранятся в журнале без автоматической очистки.
  Удаление клиента каскадно удаляет сделки, ссылки задач очищаются. Сделку нельзя
  восстановить, пока её клиент удалён. Удаления, выполненные до установки этого обновления,
  восстановить задним числом невозможно.
- Полный обмен ограничен 10 000 исходящих записей/отметок за запрос, без автоматического
  фонового запуска. Это MVP; инкрементальные пакеты и очистка журнала — следующий этап.
- После ошибки повторите обмен: UUID и временные метки защищают от дублей. Время
  последнего обмена меняется только после успешного применения ответа в SQLite.
  При первом обмене привязка организации сохраняется ещё до отправки запроса.
- Для совместимости со старыми desktop-записями email при синхронизации необязателен
  и передаётся как обычный текст. В веб-формах и основном REST API проверка формата
  email остаётся включённой.
- Пока выполняется обмен, редактирование в этом окне заблокировано; SQLite также
  блокирует параллельные записи другого экземпляра. Сетевой тайм-аут — 30 секунд.

Файлы: `app/services/sync_service.py` — HTTP-клиент и обмен; `app/repositories/sync_repository.py`
— снимок SQLite и журнал удалений; `app/models/sync.py` — привязка и время обмена;
`app/ui/sync_worker.py` и `app/ui/dialogs/sync_login_dialog.py` — фоновый запрос и вход.
На сервере: приложение `crmserver/synchronization/` — авторизация, API обмена, разрешение
конфликтов и журнал удалений. Остальные REST-маршруты и страницы сохранены.

Проверки только синхронизации:

```powershell
python -m unittest tests.test_sync_ui -v
cd crmserver
python manage.py test synchronization --noinput -v 2
```

Интеграционные тесты используют реальные desktop-сервисы и SQLite, HTTP-сервер,
веб-формы и отдельную тестовую PostgreSQL-базу, не рабочие данные.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временные базы и не изменяют рабочий профиль.

## Установщик Windows

Готовый файл: `dist/AgroSmenaCRM-0.1.0-Setup.exe` (Windows 10/11, x64).
Установщик собирается из текущего кода и включает синхронизацию и отдельный updater.
Установка для текущего пользователя, без прав администратора. Python и библиотеки
включены в комплект; интернет для установки и работы не нужен. Создаются ярлыки
на рабочем столе и в меню «Пуск», доступно удаление через настройки Windows.
Перед переустановкой или обновлением закройте CRM.

Установленная версия хранит данные в `%LOCALAPPDATA%\AgroSmenaCRM\data\crm.db`.
Удаление программы не удаляет эту базу. При запуске из исходников используется тот же
профиль; прежний `data/crm.db` автоматически копируется, если целевой базы ещё нет.
Рабочие данные не включаются в установщик.
Для переноса данных закройте обе версии и скопируйте исходный `data/crm.db`
в каталог данных установленной версии (предварительно сохраните копию существующей базы).

Повторная сборка:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File installer\build.ps1
```

Компилятор NSIS 3.12 ожидается в `.build-tools/nsis-3.12/makensis.exe` или в PATH.
Можно передать другой путь параметром `-NsisCompiler`. Официальный архив:
[NSIS](https://nsis.sourceforge.io/Download).
Сборка EXE описана в `AgroSmena.spec`, установщик — в `installer/AgroSmena.nsi`.
Инструмент сборки EXE: [PyInstaller](https://pyinstaller.org/en/stable/usage.html).

Установщик пока не подписан сертификатом издателя; Windows может показать
предупреждение о неизвестном издателе.

## Инкрементальные обновления

В desktop: **Настройки → Обновления**. Укажите HTTPS адрес `/api/app/update/`.
Цепочки ZIP применяет отдельный `updater.exe`, с проверкой SHA-256, резервной копией
и откатом. SQLite обновляется Alembic перед подтверждением новой версии.

Полная инструкция по выпуску патчей, HTTPS, восстановлению и проверкам: [docs/updates.md](docs/updates.md).
